# `PaperTradingService` decomposition plan

_Authoritative for §4 row 1 of the finish-checklist. Phase 08 exit wants `PaperTradingService` < 800 LOC as a pure facade._

## Current state (2026-05-19)

- **File**: `src/main/java/com/ttl/tabletennis/service/PaperTradingService.java`
- **Size**: 5,822 LOC
- **Public methods**: 13
- **Private methods**: 264
- **Annotations**: 74 (`@Transactional` clusters)

A class this size is a god-object. The 13 public entry points cluster cleanly into four responsibilities; the 264 private methods are mostly helpers each entry point pulls into its own corner.

## Target end-state

Four services + one facade, per §4 row 1:

| Service | Responsibility | Public surface |
|---|---|---|
| **`SessionService`** | Session lifecycle: create / reset / snapshot / bankroll arithmetic | `getSessionSnapshot()`, `resetSession()`, `getOrCreateActiveSession()` (currently private) |
| **`PlacementService`** | Live placement loop: scan recommendations, gate by policy, create bets | `syncLiveSession()` and its helpers (kelly, exposure caps, calls into the staking layer) |
| **`IntegrityService`** | Read-only observability: integrity DTO, telemetry, completed-match log | `getLiveStudioIntegrity()`, `recentCompletedMatchesLog()`, `getLiveStudioOpenBets()`, `getLiveStudioSettledTape()`, `getLiveStudioBoard()` |
| **`MatchTimelineQueryService`** | Read-only timeline + observation lookup | `getMatchTimeline(eventKey)` |
| **`PaperTradingFacade`** | Composes the four services + warm-on-startup hook | All current public methods of `PaperTradingService` continue to work via delegation |

The facade keeps the existing public method signatures so callers (`AdminController`, `LiveStudioController`, `PaperTradingScheduler`) don't have to change. Inside, each method is a one-liner that delegates to the appropriate service.

## Extraction order (low → high risk)

The order matters: each extract should be independently testable, and the most-coupled extracts come last so they can benefit from refactors that earlier extracts force.

1. **`MatchTimelineQueryService`** ⭐ landed 2026-05-19. Pure read, no transactional state, two methods (`getMatchTimeline` + its `toObservationDto` helper). Proves the decomposition pattern with the smallest blast radius.
2. **`SessionService`**: cleanest stateful service. The session is an aggregate root; lifecycle methods (`resetSession`, snapshot computation) have well-defined boundaries. Test coverage: `PaperTradingServiceTests#resetSession*` (~10 tests) verify behaviour preservation.
3. **`IntegrityService`**: read-only, shares some helpers (`matchesSettlementSource`, `safeText`, `winnerName`) with the placement loop. Move shared helpers into a utility class first, then this service comes out clean.
4. **`PlacementService`**: the big one — `syncLiveSession` plus its ~200 helpers. This is where the bulk of the LOC lives and where the most subtle state transitions happen. Should be split into:
   - **`PlacementService`** (the public entry + the per-row decision loop)
   - **`BetCandidateFactory`** (the row → BetCandidate transformation)
   - **`ExposureCapEnforcer`** (the policy-cap chain — should call into the existing `StakingPolicy` rather than duplicating)
5. **`PaperTradingFacade`**: assembles the four services + adds the `@Async warmLearningStoreOnStartup`. At this point the original `PaperTradingService` becomes a deprecated typedef for `PaperTradingFacade` to keep external callers stable, or gets deleted entirely if we audit every reference.

## Hard rules during decomposition

1. **No behaviour changes**. Each extract is a refactor, not a bug fix or feature.
2. **Tests are the safety net**. After every extract: `./mvnw test` must stay 100% green. The 60 `PaperTradingServiceTests` are the contract.
3. **Transactional boundaries don't move**. If a method was `@Transactional` it stays `@Transactional` in its new home. If it was read-only it stays `@Transactional(readOnly = true)`.
4. **Helpers move with their owners**. If a private helper is used by only one extracted public method, it moves to that method's new service. If it's used by multiple, it moves to a shared `PaperTradingHelpers` utility class (still package-private, no behaviour change).
5. **No new dependencies**. Each extracted service depends on the same repositories + services the original method depended on; the constructor is just the relevant subset.

## What "exit criterion satisfied" looks like

When this plan completes:

- `PaperTradingService.java` (if kept) ≤ 800 LOC, all methods one-line delegations.
- Four new services in `com.ttl.tabletennis.service.papertrade.*`, each ≤ 1000 LOC, each with its own focused test class.
- Full `mvn test` green, all 589+ tests passing.
- `git log --grep="paper-trading decomp"` tells a story of small, audit-friendly refactor commits.
